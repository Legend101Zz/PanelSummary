Recovered program design

Program design is the layer between architecture and code. It names the modules that take part and the contracts they exchange. It gives the exact call path and the state transitions. It also gives the failure behavior, the observability, and the test seams. It does all of this without implementation bodies.

The heart of it: the driver does not trust the agent

The agent worker returns. The director now holds a finished candidate. It discards that candidate as authority. Then it runs two separate checks.

Receipt check. The driver compares the provider and the model in the trace against the pair that policy requires. On any difference it raises: "Manga Director must use provider=... and model=...". A run on a cheaper model cannot produce an accepted artifact. The driver also refuses a trace with no provenance or no measured latency. manga_director.py:585-601

Durability check. The driver hashes the validated plan. Then it reads candidate_manga_plan_<digest> back from MongoDB. Four things must hold. The artifact must exist. Its run_id and project_id must match this run. Its validation_status must equal "valid". Its content_hash must equal the digest. On any other result it raises "MangaPlan submission was not durably validated by the domain-tool broker". manga_director.py:225-237

A model can invent an answer that looks perfect. Without a trip through the broker that answer gets nothing. The only path to an accepted artifact goes through the validators. The same pattern appears in manga_page_planner.py:311,:472 and manga_page_art_stage.py:1315.

4. The tool round trip — where the trust boundary sits

  1. The sealed agent calls a tool. It holds no database handle, no credentials, and no network exit except the broker.
  2. The broker authenticates with a constant-time comparison: hmac.compare_digest(authorization, f"Bearer {service_token}"). A failure returns 401. internal_tools.py:56-62
  3. The broker matches the tool name against a per-goal allowlist. The page lane grants exactly seven names: get_book_context, get_manga_canon, submit_page_script_set, get_page_script_set, list_relevant_assets, validate_layout_draft, and submit_thumbnail_set. page_domain_tools.py:274-283
  4. Domain errors map to bounded HTTP codes. AuthorizationError gives 403. NotFoundError gives 404. Everything else gives 422. The agent sees the bounded {code, message} only.
  5. The agent sees very little. Therefore the broker also logs on the operator side: "agent tool %s rejected (%s) run=%s stage=%s". Without that line a rejected call stays invisible to the person who debugs the run. internal_tools.py:73-80

ADR-004 states the rule that this design encodes. The tool list that an agent receives is the whole capability of that agent. Every write from an agent passes validation before it becomes durable.

5. State machines

JobStatus — v1, user facing

pending → progress* → success | failure

One document per Celery task id. It carries progress, message, phase, and extra fields such as cost_so_far. The extras become top-level fields, so the UI reads them live.

celery_worker.py:137-161

StageRun — agentic, durable

running → succeeded | failed  (attempt++ on re-arm)

The key is content_hash({run_id, stage, attempt}). On a failure, failure_history keeps the last ten entries as [*history[-9:], new], each with attempt, error, and trace. A re-armed stage increments attempt instead of overwriting.

manga_director.py:349-353, :384-420

WorkerRunState — inside the worker

RUNNING → SUCCEEDED | FAILED | CANCELLED

The key is goal.goal_id. A repeat start for a run that is RUNNING or SUCCEEDED returns the existing run. No second run starts. This is dedupe at the edge of the worker. Capacity is bounded and excess throws CapacityError.

run-registry.ts:66-76

Chain — across scopes

completed | stopped_preflight | stopped_failure

Scopes run one after another by design, because the order of the canon merge is the point. The chain stops at the first scope that does not succeed. The Session 8 receipt records stopped_failure.

whole_book.py:519-556

6. Failure behavior — four mechanisms worth your attention

A budget preflight, before any spend

A scope with a projected text or image spend above the remaining grant never starts. The chain records refused_preflight with the exact arithmetic and stops. No surprise bills arrive. whole_book.py:521-543

Failed attempts are charged as a delta, so a resume never bills twice

Failed attempts cost real money and failure_history receipts them. The executor takes a snapshot of the failed-attempt spend of the run before the stages. Afterwards it charges the delta only. Therefore a resumed scope pays nothing for the failures of a previous invocation. whole_book.py:588-593, :640-651

The transport-fallback text lane

The tool-call frame of MiniMax can mangle a correct submission in transit. Arrays arrive wrapped in {"item": ...}. Empty lists become "". Whole fields disappear. A large payload truncates mid-frame. The signature is a rejection that names fields which the model knows it emitted.

The policy answers this. After one such rejection the agent stops all tool calls. It emits the corrected object as one bare JSON assistant message. The runtime recovers that object with extractAssistantJsonCandidate, which strips <think> blocks and code fences and takes the outermost object. Then the runtime sends it through the same authenticated submit tool and the same validation gates. The fallback changes the transport. It never changes the trust model. skills/manga-page-writing/SKILL.md:140-167 · candidate-fallback.ts:29-34 · pi-runtime.ts:254-272

Free repair before paid repair, in v1

The v1 chain runs the deterministic grounding repair at zero cost and validates again. Only then does the paid quality_repair_stage run. When the report already passes, that stage does nothing. Therefore a mechanical defect never costs an editor rewrite of a 13-page storyboard. generation_service.py:242-256

7. Why resume works without a resume subsystem

No resume module exists. Resume is a consequence of three separate content-hash decisions.

  1. Scope ids are content hashes. _ensure_scope hashes the payload and calls create_scope, which returns the existing document on replay. A second plan over the same book gives the same scope ids. whole_book.py:661-686
  2. Stage keys are content hashes. The key is content_hash({run_id, stage, attempt}). A succeeded stage with output artifacts returns reused=True before any agent call. This produced reused_stages: ["manga_direction","manga_page_writing"] at $0 in the Session 8 receipt.
  3. A version guards the memory merge. _merge_plan_memory compares the compiled memory_version of the plan against active_memory_version of the project. When the canon already moved past it, the merge is skipped. This makes a crashed and resumed chain safe. whole_book.py:688-706

unproven Tests prove this against stub runners. Stage reuse also ran live in Session 8. Even so, a kill and resume in the middle of a book never ran. That is Gap 7.
