4. The v1 lane, in order

build_v2_generation_stages() builds this list at generation_service.py:212. The repair-and-check group repeats three times by design. The free deterministic pass runs before any paid rewrite.

  1. source_fact_extraction → adaptation_plan → character_world_bible → beat_sheet
  2. manga_script → script_review → script_repair an editor pass on the SCRIPT. It runs before the storyboard spends tokens on bad dialogue
  3. storyboard → dsl_validation → continuity_gate → quality_gate
  4. grounding_repair → dsl_validation → continuity_gate → quality_gate the deterministic pass costs nothing. It runs first
  5. quality_repair → grounding_repair → dsl_validation → continuity_gate → quality_gate when the deterministic pass already passes, the paid repair does nothing
  6. quality_assert → page_composition → rtl_composition_validation
  7. vector_scene → character_asset_plan → rendered_page_assembly
  8. panel_rendering → panel_quality_gate present only when image generation is in scope

Two design properties come out of this shape. First, the orchestrator is thin on purpose. It runs an ordered list and reports progress. The stages stay free of input and output. Persistence stays in the services.

Second, the code picks the stage list before the run. Therefore no stage asks “is image generation on?” inside itself. The parameter with_panel_rendering changes the list, not the stage bodies. generation_service.py:220-224

5. The agentic lane, in three layers

  1. Typed contracts. There are about 35 versioned JSON Schemas in packages/contracts/schema/. They cover manga_plan.v1, page_script_set.v1, thumbnail_set.v1, page_art.v1, compiled_layout.v1, context_pack.v1, model_receipt.v1, and eval_scorecard.v1. A generator turns each schema into TypeScript and Python. The fixtures in packages/fixtures/ hold canonical, invalid, and prompt-injection cases. The same JSON passes on both sides. This is the spine.
  2. Agent plane. apps/agent-worker is a Fastify service with authentication. It wraps packages/agent-runtime, the only package that imports the Pi SDK. ADR-003 and ADR-012 pin the SDK at @earendil-works/pi-coding-agent 0.80.10. Two instances run in development: speed (MiniMax-M2.7-highspeed, :8788) and quality (MiniMax-M3, :8789).
  3. Domain-tool broker. Agents never touch Mongo. They call back over HTTP into POST /internal/v1/agent-tools/{tool_name} on :8010. The broker uses services/domain_tools.py with a per-goal allowlist (ADR-004). The tool list that an agent receives is the whole capability of that agent. This is the trust boundary.

6. Two guards that are worth your attention

These two guards make the deprecation plan cheap to attempt. They are also the reason that “turn the flag on” carries low risk.

Compiled context cannot diverge in silence

use_compiled_context builds the slice text from a ContextPack. Then it compares the bytes against the legacy builder. Any mismatch raises. Flag-on cannot change the output quietly. It can only stop loudly.

generation_service.py:459-478 · ADR-011

The shadow lane cannot take authority

maybe_run_agentic_planning runs after a successful v1 slice. It writes rows for the agentic lane only. It logs every failure and swallows it. It adds to v1. By structure it cannot replace v1.
